## 📱 What It Does

Atelier Noir is a full-stack mobile app that acts as a personal AI stylist. Users can:

- **Register clothing items** with AI-powered analysis (background removal + category/color detection)
- **Receive outfit recommendations** generated by a 7-node multi-agent AI pipeline, streamed in real time
- **Try on outfits virtually** using the Fashn.ai API — and chain results for progressive layering
- **Sync with Google Calendar & live weather** to get context-aware outfit suggestions for the day
- **Save and review outfits** with a visual moodboard canvas

## 🤖 AI Pipeline — How It Works

### 1. Clothing Registration
When a user uploads a clothing photo, the AI pipeline runs automatically:

| Step | Model | What it does |
|------|-------|-------------|
| Detection | Rule-based | Verifies a clothing item exists in the photo |
| Segmentation | **SegFormer-B2** | Removes background, isolates the garment |
| Analysis | **CLIP (ViT-B/32)** | Identifies category, subcategory, and colors |

### 2. Outfit Recommendation — 7-Node LangGraph Pipeline

A multi-agent pipeline built with **LangGraph** streams results back to the client via **SSE**:

```
Planner → Style Analyzer → Query Builder → Retrieval → Ranker → Validator → Response
```

- **Planner**: Reads user context (weather, calendar, style preferences, feedback history)
- **Style Analyzer**: Evaluates anchor items and style references
- **Query Builder**: Assembles rule-based Naver Shopping search queries
- **Retrieval**: Fetches external items in parallel via `asyncio.gather`
- **Ranker**: Scores and sorts items against user style profile
- **Validator**: Checks outfit coherence and weather appropriateness
- **Response**: Streams final outfit proposals + commentary via SSE

### 3. Context-Aware Styling
> *"Your calendar. Today's weather. AI builds the perfect outfit for your day."*

Integrates **Google Calendar OAuth** and **OpenWeatherMap API** to inject real-world context into every recommendation prompt.

### 4. Virtual Try-On
> *"Stack your look. Try the next piece on your virtual self."*

- Powered by **Fashn.ai API** with a full production-ready backend pipeline
- **NestJS proxy layer** handles all Fashn.ai communication, with **Redis caching** to avoid redundant API calls and **AWS S3 presigned URLs** for secure garment image delivery
- Closet items use `cropS3Key` with `garment_photo_type: flat-lay` — clean background removal for accurate overlay
- External Naver items use direct URL with `garment_photo_type: model` — preserves natural draping on a model photo
- **Chained try-on sessions**: the result image from one try-on becomes the model photo for the next item — enabling progressive outfit layering, just like getting dressed in real life

### 5. Feedback Loop
- YES/NO feedback persists to `OutfitFeedback` and aggregates into `UserStylePreference`
- Cold-start protection: preference injection activates only after `total_likes ≥ 3`
- 70:30 exploitation/exploration ratio, strictly bounded by the user's Style Reference mood

## ✨ Key Engineering Decisions

**Silent failure isolation in pipelines**
Broad `try/except` blocks can mask root causes entirely. Each optional operation (e.g. anchor item SQL) is isolated in its own try/except with explicit logging.

**React Native Modal native layer**
`<Modal>` renders on a separate iOS UIWindow / Android Dialog layer. Any provider (Toast, GestureHandler) wrapping the main app tree is invisible inside a Modal — they must be re-mounted inside the modal component.

**LangGraph node contracts**
Every node's input/output is explicitly typed. The `ranker_output` is spread last in state updates to prevent upstream nodes from overwriting filtered item lists.

**BullMQ Python/Node incompatibility**
Python bullmq v2 uses BLMOVE (list-based); NestJS bullmq v5 uses Streams — they are incompatible. DB-based status polling is used for cross-language job tracking.

**Singleton model loading**
SegFormer and CLIP models are loaded once at startup and injected as constructor parameters, preventing re-instantiation on every job (which caused severe performance degradation).

**Virtual Try-On pipeline design**
Internal closet items and external Naver items require different `garment_photo_type` parameters (`flat-lay` vs `model`). The NestJS proxy centralizes this logic, keeping the mobile client simple while ensuring correct API calls to Fashn.ai.

## 🚀 Getting Started

### Prerequisites
- Node.js 18+
- Python 3.10+
- Docker & Docker Compose
- Expo CLI (`npm install -g expo-cli`)

### Environment Variables

```env
# backend/.env
DATABASE_URL=postgresql://user:password@localhost:5433/clothing_db
REDIS_URL=redis://localhost:6379
AWS_S3_BUCKET=your-bucket
ANTHROPIC_API_KEY=your-key
FASHN_API_KEY=your-key
NAVER_CLIENT_ID=your-id
NAVER_CLIENT_SECRET=your-secret
GOOGLE_CLIENT_ID=your-id
GOOGLE_CLIENT_SECRET=your-secret
OPENWEATHER_API_KEY=your-key

# ai-worker/.env.docker
DATABASE_URL=postgresql://user:password@db:5432/clothing_db
REDIS_URL=redis://redis:6379
AWS_S3_BUCKET=your-bucket
ANTHROPIC_API_KEY=your-key
```

### Run Locally

```bash
# 1. Start all infrastructure (PostgreSQL + pgvector, Redis, AI workers)
#    - clothing_db     → localhost:5433
#    - clothing_redis  → localhost:6379
#    - clothing_worker → localhost:8001  (SegFormer + CLIP)
#    - fastapi-stylist → localhost:8000  (LangGraph pipeline)
docker-compose up -d

# 2. Run NestJS backend (local, not Docker)
cd backend
npm install
npm run start:dev

# 3. Run Expo frontend
cd frontend
npm install
npx expo start
```
